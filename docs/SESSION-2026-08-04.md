## Gotchas learned this session (don't re-learn these)

- **Merging a stacked PR's parent with `--delete-branch` AUTO-CLOSES the child**,
  and a closed PR can neither be reopened nor retargeted once its base is gone.
  Retarget the child to `main` BEFORE merging the parent (#69→#70 cost a PR number).
- **A brand-new workflow cannot be `workflow_dispatch`ed from a branch** — GitHub
  404s until the file exists on the default branch. Merge-then-dispatch is the only
  path for a first run.
- **Logged-out gated pages return HTTP 200**, body = `NEXT_REDIRECT` envelope to
  `/login`, zero data. That IS the gate working. Any probe must accept this shape.
- **A 200 from www.hotelcontentradar.com proves nothing about the data layer**
  (stale ISR served through the entire 2 Aug outage).
- `posts` has a **`captured_at`** column (ingest time) distinct from `posted_at` —
  it's what makes stateless "what did the last 24h ingest" checks possible.
- `cleanup-images.js` still uses two-sentinel `hasVisibleLikes` (null/-1, not 3) —
  deliberate err-toward-keeping; change only knowingly (it's deletion logic).
- The Notion STATE note (page `38e552e4bbc781aa868ffb9f80ee9f74`) was updated
  4 Aug: changelog entry added, freshness-alarm description retired in favour of
  the digest. The connector worked this session (it's historically flaky).
- Memory file `project-safeguards-that-cant-fail.md` holds the running list of the
