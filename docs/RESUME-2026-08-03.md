## 3. Done for you

### Build isolation — safari-edit and the dashboard can no longer touch each other

This was the cause of the Vercel email flood. One repo, two Vercel projects; Root Directory tells Vercel *which folder to build*, not *when to skip* — so every push to any branch built both, and the dashboard build failed on the Supabase outage.

Both projects now carry an Ignored Build Step (`git diff --quiet HEAD^ HEAD -- .`).

Verified with a live throwaway branch touching only `demos/safari-edit`:

| Project | Result |
|---|---|
| `dashboard` | **Canceled in 3s** — skipped, no build, no email |
| `safari-edit-honeymoon` | **Ready in 4s** — built correctly |

Audited all 22 Vercel projects on the team: only these two are git-linked to `high-elm`. Nothing else in the account can be triggered by this repo.

*One limit worth knowing:* `HEAD^` compares a single commit, so pushing several commits at once where only the earlier ones touch a folder could skip a build that should have run. Merges to `main` are unaffected. If a push doesn't deploy, hit Redeploy in the Vercel UI.
